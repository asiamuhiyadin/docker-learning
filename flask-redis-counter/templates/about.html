About This Project▋

The "why" behind every architectural decision.

01 / Origin

This project began as a DevOps challenge: containerise a Python web app, add persistence, and demonstrate horizontal scaling with a reverse proxy. I took that brief and turned it into a production-flavoured reference architecture that shows the full request lifecycle — not just "it works."

02 / Design Decisions

  • Stateless Flask — no session data stored in-process, so any replica can handle any request.
  • Redis for shared state — the only place mutable data lives; containers are ephemeral, Redis is not.
  • Nginx as the sole public interface — Flask is never exposed directly, mirroring real production topology.
  • Named Docker volumes — data survives docker compose down; only --volumes wipes it.
  • Environment variables for config — REDIS_HOST, REDIS_PORT follow twelve-factor app principles.

03 / What I Learned

The trickiest part wasn't the code — it was understanding how Docker's internal DNS resolves service names at runtime, and why Nginx needs resolver 127.0.0.11 when using variables in proxy_pass. Debugging container networking with docker exec and curl from inside a container became second nature.

04 / Next Steps

  • Swap Nginx for a Traefik reverse proxy with automatic TLS via Let's Encrypt.
  • Add Prometheus metrics endpoint + Grafana dashboard for real observability.
  • Write a GitHub Actions CI pipeline to build, test, and push images on every commit.
  • Deploy to a cloud VM (DigitalOcean / EC2) behind a domain name.
  • Explore Kubernetes migration: Deployment + Service + PersistentVolumeClaim.
